# 코인 획득 기능 설계안

상태: 출석·산책·두 NPC 심부름 구현 완료. 하루 최대 550코인. 아래에는 초기 설계와 현재 구현 정책을 함께 기록합니다.

## 플레이 흐름

홈에서 오늘의 보상을 확인하고 → 마을에서 가볍게 산책하고 → 코인을 받아 → 새 소품으로 고양이를 꾸밉니다. 기존 가입 보상 1,000 코인과 구매/지갑/원장을 유지하면서 반복해서 방문할 이유를 만듭니다.

현재 구현은 **출석 보상·오늘의 산책 미션·고양이 NPC 심부름 2종**으로 구성합니다. 게시글 수에 따른 지급은 글 도배를 유도하므로 초기 보상에 포함하지 않습니다.

## 1차 보상과 화면

| 수단        | 사용자 행동                                  |      제안 보상 | 제한                    |
| ----------- | -------------------------------------------- | -------------: | ----------------------- |
| 오늘의 출석 | 홈에서 출석하기 버튼 누르기                  |       100 코인 | 계정당 하루 1회         |
| 산책 도장   | 중앙 광장·서쪽 공원·동쪽 정원의 도장대에서 E | 장소당 50 코인 | 장소별 하루 1회, 총 3곳 |
| 산책 완료   | 도장 3개를 모은 후 완료 보상 받기            |       100 코인 | 하루 1회                |

출석·산책으로 하루 최대 **350 코인**을 얻으며, NPC 심부름을 합치면 **550 코인**입니다. 모든 숫자는 조정 가능한 초기 제안값입니다. 출석 연속 기록이 끊겨도 불이익은 없습니다. 서로 다른 사용자가 같은 장소를 방문해도 각자 도장을 받습니다.

홈에 ‘오늘의 작은 산책’ 카드를 추가합니다. 출석 상태, 도장 0/3, 예상 보상과 완료 보상 버튼을 보여줍니다. 게임에서는 도장대 근처의 E 안내, 오늘 진행 상황, 지급 성공 알림을 보여줍니다. 이미 방문한 도장대는 완료 상태를 표시하고 추가 지급하지 않습니다. 비회원도 장소를 둘러볼 수 있고 보상은 로그인 후 받습니다.

코인 획득과 함께 구매 목적도 늘릴 필요가 있습니다. 기존 상품 3개는 가입 보상으로 모두 살 수 있어, 봄꽃 머리장식 600코인·민트 목도리 750코인·하늘빛 우편 가방 900코인을 추가했습니다.

## 날짜와 요청 규칙

보상 날짜는 서버의 **Asia/Seoul 기준 매일 00:00**으로 계산합니다. DB 시각은 UTC로 저장하고 응답에는 `dayKey`와 `resetsAt`을 제공합니다. 클라이언트 시계로 보상 날짜를 정하지 않습니다.

요청마다 서버가 계정, 당일 보상 종류, 이미 받은 내역, 산책 완료 조건을 확인합니다. 보상 금액은 클라이언트가 보내지 않습니다. 동일 요청이 여러 탭에서 도착하거나 응답을 잃고 재시도해도 이미 생성한 지급 결과와 현재 잔액을 반환합니다. 날짜가 넘어간 오래된 화면의 요청은 409와 갱신 안내를 반환해 새 날짜의 보상을 의도치 않게 소모하지 않도록 합니다.

## 서버 저장 구조

기존 `wallets`와 `coin_transactions`를 재사용합니다.

- `reward_claims`: id(UUID), user_id, day_key(date), reward_code, amount, created_at.
- 유일 제약: `(user_id, day_key, reward_code)`.
- 보상 코드 예: `daily_checkin`, `walk_plaza`, `walk_park`, `walk_garden`, `walk_complete`.
- `coin_transactions.reward_claim_id`: nullable FK + unique. 한 보상이 한 원장 항목으로만 연결됩니다.
- 원장의 `reason`은 `daily_checkin`, `walk_stamp`, `walk_complete`로 구분하고 UI에는 한국어 이름을 보여줍니다.

지급 순서: **지갑 행 잠금 → 서버 날짜 및 조건 확인 → 기존 지급 조회 → 보상 기록 + 원장 + 잔액을 하나의 트랜잭션으로 저장**. 기존 구매도 지갑부터 잠그므로 구매와 지급이 동시에 일어나도 잔액 갱신을 잃지 않습니다. 산책 완료는 당일 도장 보상 3개가 모두 존재할 때만 허용합니다. 실패 시 전체를 롤백합니다.

## 제안 API

| 메서드 | 경로                         | 입력/동작                                               |
| ------ | ---------------------------- | ------------------------------------------------------- |
| GET    | `/api/rewards/today`         | 서버 날짜, 다음 초기화 시각, 출석/도장/완료 상태와 금액 |
| POST   | `/api/rewards/checkin`       | `dayKey`; 출석 지급                                     |
| POST   | `/api/rewards/walk/stamps`   | `dayKey`, `spotId`; 허용된 도장 지급                    |
| POST   | `/api/rewards/walk/complete` | `dayKey`; 도장 3개 검증 후 완료 지급                    |

변경 요청에는 기존 HttpOnly 세션·Origin·CSRF 검증을 적용합니다. 성공 응답은 `claimId`, `amount`, `balance`, `replayed`, 갱신된 진행 상태를 포함합니다. UI는 보상 성공 후 지갑·거래내역·오늘의 보상 캐시를 갱신하고, 응답 불확실 시 재조회/재시도로 결과를 확인합니다. 완료 조건 미충족은 409, 미로그인은 401, 잘못된 장소 ID는 422로 응답합니다.

## 방문 검증의 한계와 확장

현재 이동과 좌표는 브라우저에서만 계산합니다. 1차 MVP에서는 정상 UI가 도장대 근처에서만 요청하도록 제한하되, API 직접 호출에 대한 실제 방문 증명은 보장하지 않습니다. **서버가 확실히 보장하는 것은 계정별 하루 지급 한도, 허용 장소, 완료 조건과 중복 지급 방지입니다.** 단순히 클라이언트 좌표를 서버로 보내는 방식도 방문 검증으로 신뢰하지 않습니다.

실시간 멀티플레이를 구현할 때는 서버가 이동 상태를 관리하고, 동일한 도장 API의 수령 조건에 서버 좌표와 도장대 거리 검사를 추가합니다. MVP를 공개 서비스로 확장하기 전 이 조건을 적용하거나, 초기 기능을 장소별 일일 선물 방식으로 안내합니다.

## 구현된 고양이 NPC 심부름

우체부 모찌에게 편지를 받아 집 옆 우편함으로 배달하면 80코인을, 상점 주인 참치의 물품을 동쪽 정원 배달대로 가져가면 120코인을 받습니다. 각 심부름은 하루 한 번이며 출석·산책과 합산한 하루 최대 보상은 550코인입니다. 준비 시간은 수락 후 20초입니다. 날짜가 바뀌면 미완료 심부름이 만료됩니다.

`quest_assignments`에 사용자·날짜·미션 코드·UUID·수락/완료 시각을 저장합니다. 사용자·날짜·코드가 유일합니다. `/api/rewards/quests/accept`는 미션 코드와 dayKey를, `/api/rewards/quests/complete`는 assignmentId·targetId·dayKey를 받습니다. 다른 계정의 UUID, 잘못된 목적지, 준비 전 완료, 지난 날짜는 거절합니다. 완료와 재요청은 기존 지급 결과를 반환합니다. 방문 검증의 MVP 한계는 NPC 배달에도 동일하게 적용됩니다.

멀티플레이 이후에는 공동 산책, 협동 배달, 공동 목표 이벤트로 확장할 수 있습니다. 초기 단계에서는 개인별 보상을 지급하고, 다른 사용자의 아이템을 먼저 가져가는 경쟁 구조는 두지 않습니다.

## 구현 순서와 확인 항목

1. 보상 기록/원장 연결 마이그레이션, 서버 날짜 계산, 트랜잭션 지급 API.
2. 홈의 출석/산책 진행 카드와 한국어 거래내역.
3. 마을 도장대 3곳, 근접 E 입력, 보상 알림과 이미 완료한 상태.
4. 구매 목적을 늘릴 소품 추가.
5. 후속 범위: 서버 기반 멀티플레이 방문 검증.

검증은 출석/도장 중복·동시 요청, 구매와 지급의 동시 실행, 완료 조건 미충족, 자정 경계와 오래된 화면, 네트워크 재시도, 로그아웃/다른 계정 전환, 재접속 및 컨테이너 재생성 후 지급 기록 유지에 집중합니다. 정상 UI의 거리 제한과 API 직접 호출의 MVP 한계도 구분해 검증합니다.
